# Development stack and data

[日本語](technology.ja.md) · [Home](../README.md) · [System design](design.md) · [Data rights and credits](research.md)

**Write the viewer in TypeScript and the offline pipeline and bus collector in Python.** The first milestone is four adjoining tiles of Shinko and one synthetic bus passing under Circle Walk. It needs no Google Maps key, ODPT token or paid image generation. These are implementation choices for the pilot. Tool versions and live route coverage will be recorded when that pilot runs.

## Components and upstream repositories

| What we build | What to use | Input → output |
| --- | --- | --- |
| City model preparation | Python orchestrates the PLATEAU GIS Converter (`nusamai`), pyproj for coordinates, and GDAL's `ogr2ogr` for vector masks. On Windows, the documented Linux CLI can run in WSL2. | Select the CityGML mesh files that intersect the pilot and export surfaces to glTF. Clip the land polygons. Record source IDs and the transform from each mesh's local origin to the shared city frame. [PLATEAU converter](https://github.com/Project-PLATEAU/PLATEAU-GIS-Converter) · [CLI releases](https://github.com/MIERUNE/plateau-gis-converter/releases) · [pyproj](https://github.com/pyproj4/pyproj) · [GDAL](https://github.com/OSGeo/gdal) |
| Background and depth | Python scripts inside Blender (`bpy`) set one orthographic camera, render color and depth, and export the camera manifest. The libvips CLI builds the color pyramid. | Local meshes → illustrated background, aligned depth and surface IDs. `vips dzsave` produces an OpenSeadragon-readable DZI pyramid. Keep depth and IDs in lossless data tiles. [Blender official mirror](https://github.com/blender/blender) · [libvips](https://github.com/libvips/libvips) · [dzsave](https://www.libvips.org/API/current/method.Image.dzsave.html) |
| Browser viewer | TypeScript, HTML/CSS and Vite. OpenSeadragon handles image navigation. WebGL2 draws vehicles, with a small GLSL ES shader for visibility against the depth map. | DZI tiles, camera manifest and vehicle snapshots → a zoomable city. Both layers share the same image coordinates when the viewport moves. Vite runs at development/build time; deployment serves static files. [TypeScript](https://github.com/microsoft/TypeScript) · [Vite](https://github.com/vitejs/vite) · [OpenSeadragon](https://github.com/openseadragon/openseadragon) · [WebGL specification](https://github.com/KhronosGroup/WebGL) |
| Live bus collector | A server-side Python process. Read static GTFS-JP using `zipfile` and `csv`. Decode GTFS Realtime Protocol Buffers with `gtfs-realtime-bindings`. | Join operator, service date and trip to the route. Emit a small JSON snapshot with source, observation time, fetch time, position and status. Store the ODPT token only in the collector. The viewer accepts the same schema from a synthetic fixture. [MobilityData bindings](https://github.com/MobilityData/gtfs-realtime-bindings) · [Python usage](https://gtfs.org/documentation/realtime/language-bindings/python/) |
| Delivery | A static host for the viewer and a versioned HTTP tile directory. Once the live layer is enabled, one collector publishes a short-lived snapshot for all viewers. | Publish the image, depth and camera under one release ID. Update a small manifest to switch releases. Hosting provider and recurring costs are open decisions. [Release design](design.md) |

Build the application in [small-yokohama](https://github.com/moruku36/small-yokohama). The repositories above are upstream tools to install or reference. Small SF's author describes the original application as closed source. [Author's making-of](https://smallsf.com/about)

## Which map and transport data to obtain

| Dataset | Files or fields to use | Pilot check and source |
| --- | --- | --- |
| **PLATEAU · Yokohama FY2024** | In the catalog select **CityGML (v4)** and the index map. Start with `udx/bldg` (buildings), `udx/tran` (roads), `udx/dem` (terrain) and `udx/brid` (bridges) wherever supplied. Use the local [study polygon](../scope/waterfront.geojson) to select meshes with a margin. | Inspect Red Brick Warehouse and the Circle Walk deck. Check source axes, units, vertical datum and glTF origin against ground control points. Use EPSG:6677 for horizontal alignment. Record the release, checksum, attribution and any manually added geometry. [Official dataset](https://www.geospatial.jp/ckan/dataset/plateau-14100-yokohama-shi-2024) · [PLATEAU policy](https://www.mlit.go.jp/plateau/site-policy/) |
| **OpenStreetMap coastline · land polygons** | Choose the full-resolution **WGS84 split land polygons** Shapefile. Clip and dissolve overlapping pieces; the part of the pilot outside the land polygon becomes harbor water. | Compare the quay edge with the PLATEAU geometry. Render pier and bridge decks separately so water does not erase them. Record the download date and ODbL credit for OpenStreetMap contributors. [Land polygons and license](https://osmdata.openstreetmap.de/data/land-polygons.html) |
| **Yokohama Municipal Bus · GTFS-JP** | Select the edition valid on the test day. Use `routes.txt`, `trips.txt`, `stops.txt`, `stop_times.txt`, service calendars/exceptions, and `shapes.txt` where supplied. | Identify Bayside Blue in both directions; verify actual trip IDs and shape coverage. If the shape is missing, show stops and times until the path can be established. [ODPT static feed](https://ckan.odpt.org/dataset/yokohama_municipal_bus) · [Operator route](https://www.city.yokohama.lg.jp/kotsu/bus/norikata/baysideblue.html) |
| **Yokohama Municipal Bus · GTFS-RT VehiclePosition** | Use the access-controlled vehicle-position resource. Retain coordinates, observation timestamp and trip reference when available. Follow the provider's display, cache and retention terms. | During service, match one fresh observation in each direction to the static trip. Label observed, stale, scheduled and synthetic markers explicitly. The catalog is confirmed; a credentialed capture for this route is pending. [ODPT VehiclePosition](https://ckan.odpt.org/dataset/b_bus_gtfs_rt-yokohamamunicipal/resource/cafd8fda-f99b-4167-9c14-c9e35cc7c42f) · [Terms](https://developer.odpt.org/terms) |

## Order of implementation

1. **One street corner.** Freeze the input versions and camera. Convert and render four adjacent tiles, then check shoreline alignment and the height of the walkway.
2. **One synthetic bus.** Load the DZI and depth in the TypeScript viewer, replay a labeled JSON fixture and inspect the occlusion as the vehicle enters and leaves the bridge. Pin the working converter, Blender and library versions.
3. **One observed route.** Connect the ODPT collector and measure the age and match rate of Bayside Blue reports. Expand to the rest of the waterfront after the [pilot acceptance checks](design.md#delivery-and-acceptance).

For a later harbor layer, Yokohama's port-call list and the Sea Bass timetable can supply scheduled events. Moving a ship as an observation requires separately licensed AIS coverage. The image-model pass, weather observations and simulated street traffic can each be added after the core map works. [Port calls](https://www.city.yokohama.lg.jp/kanko-bunka/minato/kyakusen/nyuko/2026.html) · [Sea Bass timetable](https://yokohama-cruising.jp/seabass/timetable/) · [Source register](research.md)
